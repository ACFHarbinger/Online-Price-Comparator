**Key infra decision (assume this going forward):** I added `test/__init__.py`
(making `test/` a package). Without it, pytest's `prepend` import mode puts
`test/` on `sys.path`, so `import scrapers`/`import matching`/`import dashboard`
resolve to the empty `test/<pkg>/` dirs and **shadow the real `src/<pkg>`**
packages — that broke collection of `test_cli.py`/`test_main.py` (which import
`cli` → `pipeline` → `scrapers.registry`). With `test/__init__.py` present,
pytest inserts the repo root instead, so top-level `from scrapers...` /
`from matching...` / `from dashboard...` resolve to `src/` correctly. **The next
person's tests should keep using top-level imports (`from scrapers.x import …`),
which now works.** Do NOT add a same-named subdir under `test/` that would
shadow a `src/` package without this package root in place.

**Reusable fixture available:** `test/conftest.py::in_memory_engine` yields a
fresh, schema-initialized in-memory SQLite `Engine` (StaticPool, so all
connections share the DB). Storage/repository tests in any package can depend
on it instead of spinning up their own temp file/engine.
