**Real gap found while reviewing, fixed same session (`c52969d`)**:
v2.15 Tier A's server-side custom-URL fetcher had **no code-level check**
stopping a Leboncoin.fr URL from being registered/fetched server-side,
despite yesterday's explicit policy decision (#37). Confirmed Leboncoin's
`robots.txt` has no generic `User-agent: *` block — only named bots are
covered — so an unnamed UA was technically unrestricted there even though
the site's plain-text terms forbid automation broadly. Added
`SERVER_SIDE_BLOCKED_DOMAINS` in `src/scrapers/custom_url.py`, enforced
at both the fetch boundary and the `track_and_process_custom_url`
registration boundary. Two new tests confirm zero HTTP requests happen
for a blocked domain. **Lesson for future work touching policy-sensitive
sources**: a documented decision in a roadmap file is not the same thing
as an enforced one — check the actual code path, not just the doc, when
a feature's whole point is restricting what gets fetched.
