### opencode — 2026-08-22 (v2.20 v1: localhost HTTP callback + `collection_method`)

Landed the v1 half of v2.20 per the assignment. **Commit:** `eca6c7a`
(`feat(extension): add v2.20 v1 localhost callback + collection_method
enforcement`).

**What shipped:**

- **v1 localhost HTTP callback** (`src/dashboard/extension_api.py`): a
  `POST /api/extension/import` Flask route registered on the Dash app's
  `app.server`, accepting a record object or `{"records": [...]}`. It reuses
  `pipeline.extension_import.import_records` — the same
  identity-matching → condition → FX → `persist_snapshot` path as the JSON-lines
  import, by design no trust shortcut. Added `extension/popup.js` "Send changes
  to OPC" action (configurable endpoint, default
  `http://127.0.0.1:8050/api/extension/import`) + `http://127.0.0.1/*` /
  `http://localhost/*` host permissions. The dev server stays bound to
  loopback; the endpoint is intentionally unauthenticated localhost-only.
- **`collection_method` on `site_settings`** (`server_scrape`/`client_extension`/
  `search_api`/`hint_only`, default `server_scrape`): surfaced on `SiteSetting`,
  written by `set_enabled`, and enforced by `pipeline.discover` — when an engine
  is provided it subtracts `non_server_scrape_keys()` from the scraper set, so a
  `client_extension`-flagged site structurally cannot be server-scraped. This is
  the general mechanism the doc always intended, superseding yesterday's
  point `SERVER_SIDE_BLOCKED_DOMAINS` (that fix stays, now as a defense-in-depth
  specific check).
